# Libra Search-first organic — แบบสำหรับตรวจรับ

สถานะ: ผู้ใช้อนุมัติแนวทาง Search-first วันที่ 29 ต.ค. 2026 และอนุมัติเอกสารรายละเอียดวันที่ 30 ต.ค. 2026

## เป้าหมายและเส้นตาย

ค่าลิขสิทธิ์ KDP ทั้งบัญชีมากกว่า USD 20 ในเดือนปฏิทินสองเดือนต่อเนื่อง ภายใน 90 วันนับจากวันเริ่มปล่อยงานจริง (D0 บันทึกเมื่อปล่อยจริง ไม่ย้อนวันที่) ใช้ค่าล่าสุดที่สังเกตต่อเดือน ไม่บวกรายวัน ไม่ใช้ค่าสูงสุด และแสดงว่าเป็นประมาณการ KDP ที่ปรับย้อนหลังได้ ไม่ใช่เงินโอนเข้าบัญชี

เลือกสองเดือนเต็มแรกที่จบภายใน D0+90; หากเริ่ม 29 ต.ค. คู่เป้าคือ พ.ย./ธ.ค. และประเมินครบ 27 ม.ค. 2027. หากเริ่มช้าจนมีไม่ครบสองเดือนเต็ม ให้แสดงว่าเส้นตายกับหลักฐานไม่สอดคล้องและแจ้งเจ้าของ ห้ามเปลี่ยนเป็นหน้าต่างทับซ้อนเงียบ ๆ

ยอด KDP ทั้งบัญชีเป็นผลธุรกิจที่วัดได้ ส่วนยอดที่เกิดจาก SEO ยังระบุไม่ได้ เพราะ Amazon ไม่คืนแหล่งผู้ซื้อ จึงรายงานยอดกับคลิกแยกกัน

## ประสบการณ์สาธารณะ

คง URL บทความเดิมและ operations เดิม เพิ่มหน้ารวมลูกค้าที่ `/libra/guides/` และหน้าหัวข้อแยกภาษาใต้ path นี้ ทุกหน้ามีลิงก์กลับหัวข้อและบทความเกี่ยวข้องที่อ่านต่อได้ ไม่เปลี่ยน dashboard เป็นหน้าขายโดยเงียบ ๆ และไม่เผยแพร่ข้อมูล operation เพิ่ม

ปรับหน้าบทความให้มีหัวข้อย่อย ตัวอย่างทำตามได้ และคำอธิบายหนังสือที่ตรงกับไฟล์จริง CTA แสดงรูปแบบ ภาษา และปลายทาง Amazon อย่างชัดเจน ใช้ลิงก์ติดตามเดิมภายใต้ `/libra/` พร้อม campaign SEO ที่ประกาศไว้ ไม่คัดลอกหนังสือเต็มหรือแจก EPUB

สร้าง sitemap ภายใน Libra เฉพาะหน้าที่อนุมัติแล้ว ตรวจ canonical/HTTP/ภาษา/metadata และใช้ structured data ตามเนื้อหาที่มองเห็นจริง ไม่ใส่ review/rating ปลอม ไม่ถือว่า schema หรือ sitemap รับประกันอันดับ ตาม [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview)

แสดงผู้จัดทำ วัตถุประสงค์ วิธีตรวจเนื้อหา และข้อจำกัดตามจริง ไม่สร้างผู้เชี่ยวชาญ/ประวัติ/คำรับรองขึ้นเอง เริ่มจากปรับบทความเดิมที่เกี่ยวกับเล่มผ่าน QA ก่อนสร้างใหม่

## การวัดและข้อมูล

ใช้ ledger และ signed redirect เดิม เพิ่มสถิติ aggregate ตามหน้า/วัน/ช่องทาง โดยไม่เก็บ email, cookie หรือ IP ถาวร กรอง crawler/owner/test เมื่อแยกได้ และแสดงความไม่แน่นอนของการกรอง; requests ไม่ใช่ unique people

Search Console ใช้ได้เฉพาะ property และสิทธิ์ที่มีจริง ตรวจ connected access ก่อน หากไม่มีให้รายงาน UNKNOWN สำหรับ impressions/query/index status และมีขั้นตอน setup ครั้งเดียว ห้ามใส่ศูนย์แทน UNKNOWN ห้ามเอาผล site: search เป็นหลักฐาน index ครบ

รายงานรายสัปดาห์: source freshness, impressions/clicks (ถ้ามี GSC), qualified visits ที่สังเกตได้, outbound Amazon clicks, KDP latest/month และช่องว่างจาก USD 20. ไม่มีการคำนวณ sales conversion จากข้อมูลคนละระบบ และไม่รับรอง paid order จาก orders_all_types ที่รวม free

## ลำดับ 90 วันและกฎตัดสิน

- D0–7: ตรวจคุณภาพรายเล่ม ปรับเส้นทางเข้าถึง/หน้าหัวข้อ/CTA/sitemap และ baseline; ทดสอบก่อนปล่อยจริง
- D8–30: ปรับบทความเดิมเฉพาะเล่มผ่าน QA ตามปัญหาผู้อ่าน มี semantic review ที่บันทึกได้; งานประจำเจ้าของ = 0 ไม่ติดตั้งเครื่องปั่นบทความหรือฟื้น cancelled decision agents
- D30: ไม่มี impressions ให้ตรวจสิทธิ์ GSC, indexing และคุณค่าหน้า; ไม่มีข้อมูล = UNKNOWN. มี impressions ไม่มีคลิก ให้พิจารณาคำค้น/title/intent จากข้อมูลจริง. มีคลิกเข้าเว็บแต่ outbound น้อย ให้ทดสอบความเกี่ยวข้องข้อเสนอและตำแหน่ง CTA. เปลี่ยนครั้งละประเด็นและบันทึกก่อน/หลัง
- D60: ตรวจผลเดือนเต็มแรกและแนวโน้มรายหน้า เลือกทำต่อเฉพาะหัวข้อที่มีข้อมูลรองรับ; ข้อมูลน้อยให้ INCONCLUSIVE ไม่ลบหนังสือหรือสร้างช่องทางใหม่เอง
- D90: ตรวจสองเดือนเต็ม แสดง TARGET_MET / TARGET_NOT_MET / UNKNOWN ตามข้อมูลจริง พร้อมสิ่งที่เรียนรู้และข้อเสนอรอบใหม่ ไม่มีการอ้างว่าระบบติดตั้งเสร็จเท่ากับรายได้สำเร็จ

ใช้ตัวรายงาน/ตารางงานเดิมเท่าที่เหมาะสม แผน implementation ต้องระบุ producer, command, schedule, evidence และผู้รับรายงานให้ครบก่อนเปิด automation ใหม่ การเปลี่ยน shared control surface ใช้ protocol ใน AI_WORKFLOW.md

## ขอบเขตและเกณฑ์ตรวจรับ

TOTAL KDP FREEZE คงเดิม: ไม่มีราคา metadata cover manuscript upload appeal unpublish หรือหนังสือใหม่ ไม่มี paid ads หรือ API spend ใหม่ ไม่มี Pinterest reopen, LinkedIn routine, การส่งอีเมล หรือซื้อบริการใหม่โดยแผนนี้

ตรวจรับทางเทคนิค: anonymous เปิดหน้าสาธารณะที่อนุมัติได้; draft/เล่มพักไม่ถูกโปรโมตหรือเข้า sitemap; internal links/canonical/CTA อยู่ใต้ mount ถูกต้อง; synthetic/bot ไม่เพิ่ม qualified count; unavailable data แสดง UNKNOWN; KDP guards เดิมยังผ่าน; ไม่มีข้อมูลลูกค้า/secret หลุด; ดูหน้าจอมือถือ 390px และ desktop ก่อน release

ปล่อยงาน: named-file commit + push backup; เก็บ snapshot ไฟล์ที่แก้; ตรวจ public health หลัง deploy; rollback เฉพาะไฟล์/รุ่นของงานนี้โดยรักษา state และงานค้างเดิม ห้าม reset worktree ที่มีงานผู้อื่น

## ความไม่แน่นอนและเงื่อนไขล้มเหลว

ไม่มีข้อมูลยืนยันปริมาณค้นหา/อันดับ/CTR หรืออัตราซื้อ Amazon สำหรับเล่มเหล่านี้ คุณภาพบางเล่มยังเป็นข้อสงสัย การเข้า Googlebot ไม่รับประกันว่าจะมีผู้ซื้อ แผนนี้เป็นการทดลองเพื่อให้ได้หลักฐานและรายได้ ไม่ให้ค่าความน่าจะเป็นสำเร็จที่คำนวณไม่ได้

ตรวจ spec แล้ว: ขอบเขตการแก้เว็บแยกจาก KDP, วันเริ่มอิง release, เป้าสองเดือนเต็ม, QA hold มีพฤติกรรมชัด, UNKNOWN ไม่เป็นศูนย์, ไม่มี placeholder หรือการเปิดช่องทางเดิมโดยปริยาย
