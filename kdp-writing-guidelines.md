# KDP Book Writing Guidelines

These guidelines MUST be followed every time a new KDP ebook is created — whether manually or via auto-generate.

## Pre-Writing Research (MANDATORY)

### Market Research — before choosing a topic
- Use web search to find trending KDP niches and bestselling categories
- Search in both English AND the target language marketplace
- Look for: high demand + low competition topics
- Cross-reference with existing books to avoid saturation
- Save findings as `market-research.md` in the book directory

### Content Research — before writing the book
- Use web search to find 8-12 real, credible sources about the chosen topic
- Sources should include: expert articles, research papers, official guidelines, real statistics
- Fetch and read the most important sources in detail
- Extract key facts, data points, and expert recommendations to use in the book
- Save findings as `content-research.md` in the book directory
- These sources become the book's Vancouver-style references — NEVER hallucinate references

## Author
- Always use **WK Bui** as the author name in metadata.yaml and in the book text
- NEVER use "IncomeinClick"

## Length
- Minimum **10,000 words** and **40 actual paperback pages** at 6×9 format
- If the generated PDF is below 40 pages, the book must not be published
- Add substantive chapters, examples, exercises, and step-by-step guidance; never pad with repetition

## Language Purity
- Write **entirely** in the target language. Do NOT switch to English mid-sentence or mid-paragraph
- Technical brand names, well-known abbreviations (AI, GPS, PDF), and proper nouns may stay in their original form
- All explanatory prose, headings, bullet points, and captions must be in the target language

## Structure
- Use clear hierarchy: **Parts → Chapters → Sections**
- Start each chapter with a relatable hook or real-world scenario before diving into content
- End each chapter with a brief summary or key takeaway
- Include a FAQ chapter addressing common reader questions
- Include actionable checklists or step-by-step plans the reader can follow immediately

## Reader Comprehension
- Write so a **complete beginner** can follow
- Use concrete examples, analogies, and practical steps — not abstract theory
- Explain technical terms in plain language the first time they appear
- Use a conversational but professional tone

## Markdown Structure (Critical — Controls TOC Accuracy and PDF Layout)

These rules prevent the three most common PDF defects: wrong TOC page numbers, blank-looking pages, and headings separated from their content.

- **NEVER start with `# Book Title`** — the title page is auto-generated from metadata.yaml. Writing the title as a `#` heading causes it to appear twice (title page + chapter heading) and pollutes the TOC.
- **NEVER write an inline TOC** (`## Inhaltsverzeichnis`, `## Table of Contents`, numbered chapter list, etc.) — the TOC is auto-generated by pandoc with correct page numbers. An inline TOC creates a duplicate TOC and causes all TOC page numbers after it to be wrong.
- **Start content directly with `## Preface` heading** (e.g., `## Über dieses Buch`, `## About This Book`) — this becomes the first real TOC entry.
- **Use `#` heading only for major structural parts** (e.g., `# Teil 1: Grundlagen`) — each `#` heading forces a new page. Only use for real high-level divisions.
- **Do NOT use `---` as page separators** — it creates a horizontal line, not a page break, and wastes space.
- **Each `##` and `###` section must have ≥ 150 words** — a heading with only 1-2 sentences below it creates a near-empty page.

## Interior Art
- Default to a professional text-first interior with no generated images
- Do not insert Markdown or HTML image tags unless a future edition explicitly enables and discloses AI images

## Formatting for PDF (Prevent Overflow)
- **Tables:** Keep simple — max 4-5 columns. Use short text in cells. Avoid wide tables with long descriptions
- **Lists:** Use bullet points for pros/cons/steps. Keep list items concise (1-2 lines each)
- **Page breaks:** Do NOT put multiple short sections on the same concept — consolidate into one longer section
- **Paragraphs:** Keep paragraphs short (3-5 sentences max). Use bold for key terms

## Research References
- ALL factual claims must have numbered citations `[1]`, `[2]` etc. from your content research
- Add a **references appendix** at the end using **Vancouver citation style**
- Title the appendix in the book's language (e.g., "Quellenverzeichnis" for German, "Referencias" for Spanish)
- **ALL references must be REAL URLs found during content research** — NEVER invent/hallucinate sources
- Minimum 8 references from your web research
- Include the actual URL for each reference so readers can verify

## Vancouver Citation Format

```
[number] Author(s). Title. Place: Publisher; Year. Available from: URL
[number] Author(s). Article title. Journal. Year;Volume(Issue):Pages.
```

Example:
```
1. Europäische Zentralbank. Harmonisierter Verbraucherpreisindex. Frankfurt: EZB; 2024. Verfügbar unter: ecb.europa.eu/stats
2. Markowitz HM. Portfolio Selection. J Finance. 1952;7(1):77–91.
```

## Book Ending
- End with a motivational closing chapter encouraging the reader to take action
- Include a "Resources" section with useful websites/tools
- Include the references appendix (if applicable)
- End with a disclaimer appropriate to the topic

## Automated Publish Gate
- Exactly 7 unique backend keyword phrases, each 2-50 characters
- At least 2 relevant KDP categories
- Description length 150-4,000 characters
- At least 8 numbered references and 8 valid source URLs
- Every numbered in-text citation must have a matching reference
- No duplicate headings
- EPUB, cover, research files, and a 40+ page paperback PDF must exist before upload
